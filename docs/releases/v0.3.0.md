# v0.3.0 — optional blood CH and RNA neoantigen execution

Prepared26 November2026 on v0.2.0, incorporating the completed
`chip/reporting-layer` source at `b618a90` and tested optional execution code at
`2818716`. The owner explicitly authorized direct Git merge, numbered tag and
publication for this promotion; future work retains the normal PR policy.

The native FASTQ entry runs the unchanged Hartwig stack and then the independently
selected blood CH / RNA-informed neoantigen Nextflow branches. Eligibility uses
bound laboratory metadata; disabled, ineligible, missing, failed and completed
states remain distinct. Blood CH retains paired tumour counts and the recorded
purity/ploidy infiltration model with its stated limitations. CH candidates are
research results, not a clinical CHIP diagnosis. Patient-report prose is unchanged.

The review-only entry reuses completed VEP/prediction outputs. The explicit
pVAC aggregation preserves the recorded standalone RNA thresholds and expression
argument rather than inheriting different automatic defaults. CH staging links
are removed before copy-publication, preserving native source BAMs and avoiding
accidental BAM duplication. See [extension validation](../../tests/results/optional-extensions/README.md).

Fir now has an explicit site environment, Slurm/Apptainer configuration and
simple `run_native_fir.sh --manifest ... --config ... --blood-ch` entry. New
packages use project releases/resources, canonical scratch FASTQs and versioned
analysis roots. Frontenac defaults and existing issued jobs remain unchanged.
BWA keeps64CPUs with lane-local RAM/time. The supplied Fir production ceiling
is64CPUs/768GiB/7days. The launcher records its head ID and preserves manifest,
release and options on resume. [Human guide](../FIR_EXECUTION.md).
