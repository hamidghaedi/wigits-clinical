# WiGiTS v0.1.0 — consolidated native execution release

Date: November23,2026. First repository-wide release, incorporating the
published `hartwig_adoptation` history through `7a8f207`. Existing component
tags keep their identities. This promotion adds release documentation and
current branch instructions; it does not change launcher/scientific source.

For this promotion only, the owner explicitly authorized a normal Git
merge/push without a pull request after GitHub's integration rejected PR
creation with HTTP403 (`Resource not accessible by integration`). Published
history is preserved and no force-push is used. The normal pull-request
procedure remains the policy for subsequent work.

## Included

- Native original-FASTQ Oncoanalyser entry, all recorded lanes and mates,
  frozen-package execution and lane-local BWA sizing at64CPUs with input-v4.
- Existing source-aware ORANGE corrections, RNA duplicate policy and explicit
  diagnosed runtime recovery tools.
- Read-only native somatic QC, targeted SNP support, CPU/memory/queue reporting.
- Explicit experimental BAM/DeepSomatic/context-export routes and their existing
  tests/evidence. Their source is retained, not enabled as the routine default.
- `main` as the maintained integration branch, `VERSION`/`VERSIONS.md`, and the
  documented [upstream update procedure](../RELEASING.md).

The default scientific stack remains oncoanalyser3.0.0, native SAGE, the
GRCh38_hmf genome and HMF3.0.0--8 resources. Default local source
3.0.0-qlmp.2.2 retains its ORANGE source-value corrections. Official GitHub
latest-stable metadata checked November23 still selects3.0.0. No new reference,
container, environment, report-template or clinical-layer implementation is
introduced. The standing new-FFPE route decision is still open; issued batch
exceptions retain their scope.

## Execution and subsequent updates

Use this tag/exact commit when issuing a new package through the existing
native entry. Record the actual source/reference/container bindings. Existing
queue deployments, running attempts, work/cache, historical tags and reports
retain their versions; no automatic redeployment is implied by this release.
Future changes branch from current `main`, receive the appropriate comparison,
and return through a pull request as a new numbered release.
